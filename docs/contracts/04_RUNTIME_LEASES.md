# Ejecución, memoria, leases y compatibilidad

RuntimeVersion.version_string no usa SemVer obligatorio; identidad runtime_id+upstream_commit/build+artifact hash+channel. Installation strategies canónicas de §52: PREBUILT_BINARY, GITHUB_RELEASE, SOURCE_BUILD, WINGET, PIP, UV, CONDA, MAMBA, NUGET, WSL, CONTAINER, CUSTOM. Se conservan como extensiones explícitas MSI_MANAGED, PYTHON_VENV y EXTERNAL_ADOPTION. El adaptador anuncia installation_strategies; una estrategia no anunciada se rechaza con UNSUPPORTED_CAPABILITY antes de IO. Ningún runtime está obligado a implementar todas. Correspondencia histórica sólo para migración de datos: ARCHIVE->PREBUILT_BINARY, BUILD_FROM_SOURCE->SOURCE_BUILD, WSL2->WSL; no sustituir UV/CONDA/MAMBA por PYTHON_VENV. MSI global no autorizado no se fuerza: modo external o BLOCKED_REAL. NUGET resuelve versión/arquitectura/hash+deps lock a carpeta local; restore privado aislado. Python venv por runtimeversion/backend/lock hash; pip hashes, sin site-packages global ni installer shell remoto. Containers image digest inmutable; WSL distro explícita preexistente. Adapter mapea comandos/APIs en un profile lock por versión; no flag supuesto si --help difiere.

Hardware snapshot: OS edition/build/architecture; CPU vendor/model/logical/physical/instructionsets; RAM physical/usable; GPU vendor/device/LUID, dedicated/shared/unified pool; NPU ID; driver exactos; APIs detectadas y probadas; software dependencias; storage class. Sólo hardware estable entra fingerprint; RAM libre, temperatura, carga, driveletter, uptime no entran. Probe sin soporte=>UNKNOWN con reason. No codificar CPU/Radeon del usuario por conjetura.

LaunchProfiles: ECO threads=max(1, floor(logical/2)), concurrency1, context=min(2048, model_limit); BALANCED threads=max(1, physical-1), concurrency1, context=min(4096, model_limit); PERFORMANCE threads=max(1, logical-1), concurrency1, context=min(4096, model_limit); LONG_CONTEXT threads BALANCED, concurrency1, context=model_limit limitado por admission; CUSTOM requiere campos explícitos. Backend solicitado concreto; no cambiar a CPU sin que constraints.allow_backend_fallback=true. Offload layers AUTO sólo si adapter estima y reporta layer_count efectivo; unknown no puntúa GPU. Cada effective profile completo se persiste y hash incluye parámetros, seed, context, batch, threads, offload, template/tokenizer y protocol.

Memory estimate para transformer: weights según bytes tensores+buffers adapter; KV=2*layers*kv_heads*head_dim*context*batch*kv_bytes (ceil para bits), activations/scratch adapter por modelo, runtime overhead=max(256MiB, ceil(weights*0.1)); total_checked=sum componentes. Sin metadatos no inferir KV del nombre: UNKNOWN y no auto-admitir salvo budget hard del operador. Multimedia requiere estimator del adapter que incluye resolución/frames/duración, temporales y workspace; no reutilizar fórmula LLM. Unified memory deduplica RAM/VRAM del mismo pool. Budget=pool_total-max(4GiB, ceil(total*0.1)); usable=min(budget-reservas_LARM, OS_available-reserve). Memory reservations por pool, checked y atómicas. Medidas reales actualizan sólo ese fingerprint, sin esconder estimación inicial.

Scheduler prioridades PINNED100, HIGH80, NORMAL40, BACKGROUND10; Broker pide HIGH, benchmark BACKGROUND y manual NORMAL; tie FIFO created_at, id. Arranque máximo1; reserva memoria+artifacts antes de proceso. Admisión sin memoria espera hasta300s, devuelve RESOURCE_UNAVAILABLE retryable, nunca evict ACTIVE lease. Unload sólo instance sin leases después300s idle; elegir lowest priority, last_used_at, id. Recursos ajenos se consideran presión observada; no matar proceso ajeno.

Leases API ver api-operations.json y schemas: POST /leases {variant_id|null, capability, launch_profile_id, constraints:{runtime_version_id|null, backend_id|null, execution_fingerprint|null, allow_backend_fallback:false, max_memory_bytes|null}, ttl_seconds:120, owner_id, request_id}. Una de variant/capability obligatoria; constraints exactas nunca relajadas. Respuesta ACTIVE {id, owner_id, instance_id, generation, endpoint_id, endpoint:{base_url, protocol, credential_reference}, execution_fingerprint, expires_at, renew_after_seconds:40}. No exponer rutas de pesos ni secrets. Request idempotent. Si tarda:202 Operation; polling hasta ACTIVE/FAILED; el cliente no usa endpoint antes de ACTIVE. TTL permitido30..600; renew repone desde ahora, no acumula; mismo owner e If-Match row_version. Grace30s impide nuevas admisiones de esa lease; al expirar revoca token endpoint, no kill mientras llamada activa dentro grace; timeoutcancel con resultado registrado. Release idempotent204 incluso already released; owner equivocado403. Restart invalida generations y leases sólo se recuperan tras PID+starttime+exe hash y nuevo handshake; no persistir ACTIVE por mera fila DB.

Supervisor usa Windows Job Object kill-on-close para procesos propios, executable+args, cwd/env allowlisted; captura PID+creation_time+exe_sha256+generation; adopter externo jamás kill. Reserva port bajo lock global en rango20000..29999 y binding prueba; no cerrar proceso que ocupa puerto. START120s, LOAD600s, health5s cada10s, stopgrace15s, 3 crash restarts por10min [1, 5, 15], después FAILED. LARM close GUI no cierra daemon. stdout/stderr bounded y sanitizados.

Hard gates por tuple variant/runtimeversion/backend/hwfingerprint/profile: format, architecture, ops, quantization, ISA, OS, drivers, EP, license/trust, bundle_integrity, memory, protocol. Cada PASS/FAIL/UNKNOWN con evidence. FAIL=>INCOMPATIBLE; UNKNOWN=>UNKNOWN; CONVERSION_REQUIRED etc sólo si un pipeline exacto soportado existe, no disponible ahora. COMPATIBLE exige todos PASS; limitations deben ser explícitas constraints, no excusa para fallo oculto. Smokes confirman backend efectivo y fallback. Backend detectado no equivale operable; carga modelo pequeño real y evidencia requerida.

Auto-unload configurable NEVER, IDLE_TIMEOUT, MEMORY_PRESSURE, LRU. NEVER no descarga automáticamente; IDLE_TIMEOUT300s sólo sin leases/pin/warm; MEMORY_PRESSURE evict lowest priority y más antiguo idle; LRU last_used_at asc con priority como guard. PINNED y configured warm quedan protegidos salvo un cambio explícito de política aprobado; active lease nunca evictable. Runtime describe limits max_instances>=1, multi_model_support bool, parallel_requests>=1, gpu_sharing bool; scheduler impone mínimo de límites host/adapter/profile y no crea instancia adicional si no soportada.

Entrega exacta de credenciales de endpoint: named pipe local \\.\pipe\LARM-{sha256(SID)[0:16]}-credentials con PIPE_REJECT_REMOTE_CLIENTS y ACL de los SID configurados. Mensaje NDJSON {request_id, lease_id, generation, credential_reference_id, bearer_token}; validar principal, scope leases:manage, propietario y generation ACTIVE. Respuesta {request_id, token, expires_at}; token sólo en memoria del Broker, nunca reporte/log/CLI. Pipe requiere nonce de sesión de un uso y máximo4KiB; Credential Manager almacena service=larm/lease/{lease_id}, username=owner_id, secret de256bits generado con CSPRNG. Config de cuenta de servicio añade SID explícito después de enrolamiento, no copiar credenciales de otro usuario. Release/expiry elimina referencia y revoca gateway. Endpoints propios se exponen por gateway autenticado; raw listener sólo bajo la frontera local declarada en profile y con prueba de aislamiento. Un host externo sin autenticación no se describe como aislado de todos los usuarios del PC: modo EXTERNAL_LOCAL_TRUSTED exige aceptación explícita de esa limitación antes de Broker eligibility.

Handshake de pipe: al conectar, servidor envía {nonce, expires_at} con nonceCSPRNG32bytes válido60s; solicitud anterior añade nonce. El servidor lo consume una sola vez, verifica Bearer/owner/generation y tamaño antes de responder. No aceptar pipe remoto ni recuperar token de un lease ajeno.

MemoryEstimate separa multimodal_bytes y temporary_bytes. base=sum(weights,KV,activations,workspace,runtime_overhead,multimodal,temporary) con checked math; safety_margin=max(512MiB,ceil(base*500/10000)); total=base+safety_margin. Reserva de sistema y margen de modelo son conceptos distintos y ambos visibles. No contar buffers compartidos dos veces; adapter declara allocations por pool. Hardware snapshot sigue el schema cerrado y sólo observed_metrics se excluye de hash; componente estable null conserva UNKNOWN.

Canonicalización del hardware antes de RFC8785: ordenar instruction_sets; devices por kind+device_id+vendor; dependencies por name+version+hash; listas de backends por ID. LUID sirve para binding dentro de la sesión y se excluye de HardwareFingerprint porque puede cambiar al reiniciar. También se excluyen observed_metrics y evidence_refs/timestamps. Device ID estable y topología de memoria sí participan; si no se pueden identificar quedan null/UNKNOWN, no se inventan.

Recursos por petición: LeaseRequest y estimador incluyen ResourceRequirements (context/output tokens,batch,resolución,frames,sample rate,duración,budget duro). Broker los obtiene del input contractual antes de pedir lease. Null en context/temperature/top_p/output_tokens indica no aplicable, no un valor mágico para audio/tensores. Perfiles de texto siguen los defaults cerrados; capacidades sin tokens excluyen contexto del score. Si requirements=null, reservar sólo modelo residente; antes de cada invocación el gateway/sidecar valida input y reserva workspace del mismo pool con estimador del adapter. No enviar trabajo al runtime sin admission. RESOURCE_UNAVAILABLE previo a dispatch es reintentable; superar techo total es terminal. Liberar buffers de petición al terminal conservando reserva residente hasta unload, sin doble conteo.

Renewal timing: renew_after_seconds=min(40,max(1,floor(ttl_seconds/3))); default120s da40s,TTL30s da10s. TTL se mide con reloj monotónico durante la sesión; expires_at UTC es representación, no una forma de extender reserva por cambio de reloj. Al reiniciar, reconciliar identidad/generation y expirar conservadoramente si no hay confirmación del propietario. POST renew exige If-Match e Idempotency-Key. owner_id debe coincidir con principal autenticado, no es un permiso para suplantar otro owner.

Las representaciones y reglas de los requisitos corregidos están completadas en [contrato 11](11_CONFORMIDAD_V3.md); aplicarlas junto con este contrato.
