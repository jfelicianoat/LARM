# Interfaz, agente de fondo y entrega

La navegación tiene14 pantallas: Inicio, Descubrir, Mis modelos, Runtimes, Instancias, Hardware, Almacenamiento, Descargas, Benchmarks, Actualizaciones, Fuentes, Adaptadores, Notificaciones y Configuración. API es autoridad de elegibilidad y reservas. Todas las pantallas muestran loading, empty, offline, error, retry y confirmación de estado durable. Idioma español, unidades IEC con bytes exactos en detalle, hora local sobre UTC persistido. Accesibilidad WCAG2.2AA: teclado, foco, labels, contraste y reduced motion. Secretos nunca vuelven al formulario.

Hardware muestra OS, CPU, RAM, GPU, NPU, drivers y EPs con fuente, evidencia, last_probe y estado verificado/declarado/desconocido. Refresh inicia un job, sin instalar drivers. Almacenamiento permite CRUD de name, root, priority, auto_placement, reserve_bytes y performance_class; Volume GUID es de sólo lectura. Validar ruta y permisos antes de guardar. Dos roots del mismo volumen muestran presupuesto compartido. Move muestra lease blockers, plan aprobado y fases; cleanup muestra referencias y dry-run. Una unidad offline conserva registros.

Runtime wizard: familia, estrategia, versión, backend, host, prerequisitos, permisos, ownership gestionada/externa y prueba real. Source wizard: tipo, base_url/root, auth_mode, credential_reference, licencia/gated y probe. Todos los tipos de source-profiles deben estar accesibles. Error de auth no equivale a catálogo vacío. Descubrir expone todos los filtros y los tres toggles de §108 mediante Search: texto, capacidad, arquitectura, parámetros, formato, cuantización, runtime, fuente, licencia, tamaño, compatibilidad, confianza y certificación; sólo ejecutables, sólo recomendados y mostrar incompatibles. Backend puede ser información adicional, sin reemplazar runtime. Mostrar revisión exacta, tamaño/confianza, score técnico provisional y calidad NO EVALUADO. No fusionar modelos por nombre.

Download muestra destino, bytes finales/extra/temporales, margen, reservas y causas de rechazo. UNKNOWN exige presupuesto duro antes de admitir. Model detail muestra ubicación física resuelta, fingerprint, provenance, ownership, lease_count, etapa y disponibilidad por separado. Promotion dialog compara candidato/default, eje, diferencias, smokes, benchmark, evaluación y pinning. UNKNOWN o INCONCLUSIVE bloquea el botón de promoción.

Configuración cubre todos los campos de schemas/larm.schema.json Settings: paths, API, TLS y credential reference remota, origins, autostart, modo servicio/cuenta, storage/presupuestos/cuotas, auto-placement, auto-download policy, watchers, perfiles por defecto, pin/warm, benchmarks, retención, privacidad, diagnostics, registry_url, registry_allowed_origins, publisher_keys Ed25519 fijadas y permisos. Registro remoto apagado con URL null; el estado muestra secuencia, vigencia, última verificación y revocaciones sin llamar trust al índice. Import/export muestra el hash ZIP, identidad/familia, permisos, estado de firma/confianza separado de cualificación y job recuperable; jamás muestra paths internos del journal ni secretos. Añadir import/export de adaptadores y editor CUSTOM_RULES con validación/preview. Settings usan If-Match, CAS y outbox, sin guardado optimista falso. Cambiar parámetros de benchmark crea nueva suite/settings revision. Null en defaults permite el valor tipado posterior, no un campo sólo-null. Expandir sólo LOCALAPPDATA/PROGRAMDATA, nunca shell. Remote exige certificado/key válidos, bind explícito, token y origins exactas. Auto-download exige cuota, allowlists, destino y licencias.

Fuentes privadas: TOKEN/OAUTH_DEVICE/SSH/COOKIE/GIT_LFS/NONE según profile. Device flow muestra scopes/user_code/URL/expiry, respeta intervalo y revocación; refresh y device_code sólo en almacén protegido. SSH usa agent o key protegida, host key fijada y sin verify bypass. Cookies respetan domain/path/expiry/secure, sin extracción de navegador. Git LFS valida OID SHA256 y size; pointer no es modelo. Unsupported auth se muestra explícitamente. Aceptación de licencia se liga a license_hash+account+revision; no aceptación automática.

Daemon default USER_AGENT por usuario con mutex SID, bootstrap named pipe protegido y GUI attach. Cerrar GUI mantiene jobs/instancias. Autostart opt-in mediante tarea por usuario. WINDOWS_SERVICE requiere instalación explícita/elevada, cuenta de servicio y ACL de config/data; no depender de unidades mapeadas de sesión. Contexto de Credential Manager separado: enrolar credenciales de esa cuenta, sin copiar secretos de usuario. Mostrar limitación y procedimiento. Stop drena leases y jobs antes de terminar workers propios.

Installer fija toolchains y lockfiles de P000/P001, detecta MSVC/WebView2, conserva modelos/DB al desinstalar por defecto. Firma sólo se afirma con clave/firma reales; build unsigned se identifica. Updater: staging, hash/firma, bloquear admisiones, drain hasta600s y defer si siguen leases, SQLite online backup con WAL/config/manifests, migración, readiness y rollback de binario+DB compatible desde backup íntegro. Mantener versión anterior. Rebuild no reconstruye secretos desconocidos.

Performance gates: catálogo100000, artefactos10000 y jobs100; GET p95<=250ms warm, primer resultado UI<=1s, cancel ack<=2s, daemon idle CPU<2% durante1min y RAM<250MiB sin worker, outbox1000events/s sin pérdida. Probar10 admissions/10 moves concurrentes sobre los mismos recursos. Guardar contexto hardware; no bajar umbral después de observar fallo. Diagnostics ZIP<=50MiB, logs14d, sin prompts/respuestas/tokens/cookies/Authorization; paths personales sólo opt-in. Redaction tests con secretos señuelo.

Auth de §16 completa: BEARER y API_TOKEN distinguen cabecera exacta del profile; TOKEN es alias legado, BASIC guarda username/password sólo en Credential Manager (POST basic-credential protegido) y no imprime Authorization base64. OAuth AUTH_CODE_PKCE usa S256, verifier CSPRNG32bytes protegido, state CSPRNG32bytes de un uso, callback exacto loopback registrado y caducidad300s. Callback es la única excepción auth adicional a health/live: requiere state válido y verificación PKCE antes de intercambio con HTTPS/source origin. Query code/state jamás en logs; error limpia flow sin tokens. Device flow conserva su intervalo y slow_down+5s, expiry y revocación. Sólo habilitar los flows que el profile oficial de la fuente soporta.

Las representaciones y reglas de los requisitos corregidos están completadas en [contrato 11](11_CONFORMIDAD_V3.md); aplicarlas junto con este contrato.
