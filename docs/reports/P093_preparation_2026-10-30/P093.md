## Implementación concreta

### Requisitos corregidos de la revisión 3

- H07: Persistir FAILED_RECOVERABLE en transformaciones no reanudables interrumpidas, causa y journal. Reinicio exige input íntegro, nuevo preflight, guard/reserva y attempt incrementado. Emitir evento y mostrar acción Reiniciar; COMPLETED/CANCELLED permanecen terminales.

Preflight por fase y volumen; input inmutable, herramienta/versión/parámetros hashlocked y provenance. No borrar original antes de verificar derivado y smoke.

### Checklist funcional conservado

1. Entidad TransformationJob con input artifact hashes, tool/runtime version, params canonical JSON, output expectations.
2. Preflight storage calcula coexistencia de input/temp/output.
3. Worker externo por herramienta.
4. Outputs sólo se registran tras hash + load/smoke hook cuando exista runtime validator.
5. Cleanup conserva input por defecto; policy keep/delete-after-verified/ask.
6. Crash leaves journal and recoverable state.

Las representaciones y valores del contrato normativo sustituyen ejemplos de campos anteriores. Este checklist conserva funciones, no habilita una representación alternativa.

Aplicar exactamente las rutas, firmas, fields, enums, transiciones, límites, fórmulas y errores de los contratos. Una instrucción «definir» significa materializar el contrato adjunto, no elegir otro diseño. No convertir unknown en dato verificado ni protocolo candidato en soporte. Actualizar API/DTO/DB/UI afectados y su documentación en el mismo incremento.

Debes crear o modificar, como mínimo, las áreas siguientes cuando correspondan al estado real del repo:

- `crates/larm-transform/*`
- `migrations/*transform*.sql`
- `crates/larm-api/*transform*`

## Pruebas y oráculos

Casos de cierre de conformidad v3 (contrato 11):

- H07: Interrumpir una transformación no reanudable; reconciliar, persistir y consultar FAILED_RECOVERABLE.
- H07: Reiniciar bajo nuevo preflight y comprobar hash intacto del original, tratamiento de temporales y trazabilidad del intento anterior.

Los schemas y el verificador del paquete solo prueban representación documental. Ejecutar estos oráculos contra los casos de uso y, cuando implican IO/proceso/UI, contra el daemon/worker reales antes de REAL_PASS. No sustituir conducta por comparar constantes.

Implementa y ejecuta al menos:

- Disk insufficient.
- Tool crash.
- Hash mismatch.
- Recovery.

Añadir los casos negativos de los contratos aplicables: schema inválido, autorización insuficiente, estado inválido, timeout/cancel, fallo de IO o proceso y recuperación. Para un módulo puro verificar determinismo y serialización; para IO verificar state+journal/outbox+reservas bajo fault injection. El test debe observar conducta, no repetir el algoritmo.

Prueba real obligatoria: Ejecutar el comportamiento de este módulo en Windows/PC IA sobre datos y ubicaciones de prueba; confirmar los contratos citados y registrar evidencia real. Un requisito no aplicable al hardware exige causa y prueba del rechazo correcto; equipo ausente no es inaplicable.

Registrar inputs/fixtures, hashes, versiones exactas, fecha, host, expected/observed y test IDs. No tests omitidos etiquetados PASS. Probar mocks es útil para CODE_PASS; cada aceptación real sigue pendiente hasta ejecutarse.

Checks: cargo fmt --check; cargo clippy --workspace --all-targets -- -D warnings; cargo test --workspace; tools/check.ps1 -Prompt P093 -Real. Frontend afectado: npm run lint, typecheck, test, build.
