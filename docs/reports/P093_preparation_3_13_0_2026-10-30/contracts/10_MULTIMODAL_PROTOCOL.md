# Protocolos y capacidades

capability-contracts.json fija18 capacidades iniciales de §20, con schemas de input/output. Registro abierto: una nueva capacidad requiere ID namespaced, versión, schemas con hash, protocol mapping, estimador de recursos, fixture y conformance. Core valida por descriptor, sin cadena if runtime/source. Aliases sólo lectura; salida usa ID canónico. audio.vad/kws/speaker/language son extensiones de sherpa y requieren descriptor completo antes de anunciarlas.

Sidecar usa protocol.invoke, valida input y output por schema y ejecuta librería/CLI fuera de Core. Media input es artifact_ref con SHA; no fetch de URLs arbitrarias. Tensor usa dtype/shape y bytes exactos little endian; comprobar product(shape)*dtype_bytes con checked math antes de allocation. Inputs readonly, outputs bajo root de lease, cuota y timeout de job. Comandos executable+args. Outputs binarios se guardan como artifacts, sin base64 en estado sondeado.

Texto SSE: start {request_id, sequence:0, fingerprint}; delta {request_id, sequence, text}; tool {request_id, sequence, tool_call}; done {request_id, sequence, usage, finish_reason}; error {request_id, sequence, error}. Secuencias monotónicas, exactamente un terminal; disconnect cancela y libera lease. Delta vacío/role no cuenta TTFT. LARM entrega tool name/args validados y Broker orquesta herramientas. OpenAI/Anthropic subsets se declaran en profile por versión, con mappings de finish/errors/tools probados; un subset no se presenta como API completa.

Extensión NUEVA en Broker: POST /api/v1/capability-tasks recibe CapabilityTask strict, con input validado por descriptor. Devuelve202 y replay200; mismo conflicto de idempotencia que tasks. GET /api/v1/capability-tasks/{id}, artifacts/invocations y DELETE cancel reutilizan envelopes contractuales Broker. Exactly1 artifact final con SHA. Flujo asíncrono, sin prometer streaming al cliente. Capabilities añade mapa capability_contracts ID→version/schema hashes. /tasks chat/embedding sigue compatible. Provider larm adquiere lease y reutiliza scheduler único y data boundary. La extensión existe sólo después de P108 en repo BrokerPCIA; inference_kind:image no es válido en2.11.

Decision.evaluate traduce a System1judge existente sólo cuando provider/profile coincide con contrato15.1; cloud_allowed false, modelo efectivo y attempts raw. Otras capacidades usan provider adapters, canonical artifacts y telemetría contractual. Artifact410 es indisponible, no se regenera en silencio. Capacidad no anunciada devuelve409 CAPABILITY_UNAVAILABLE antes de lease. Schemas necesarios ausentes: CONTRACT_UNSUPPORTED. No degradar a chat para fingir cobertura multimodal.
