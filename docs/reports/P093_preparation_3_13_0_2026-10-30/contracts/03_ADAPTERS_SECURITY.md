# Adaptadores y frontera de seguridad

Cinco familias obligatorias: runtime, source, protocol, transformation, benchmark. Adapter manifest: id, version (string), family, protocol_version=1.0, publisher, executable {relative_path, args:string[]}, platforms, architectures, methods:string[], installation_strategies:string[] del enum InstallRequest (vacía si no instala), permissions {read_roots, write_roots, network_origins, process_allowlist, secret_refs}, capabilities, package_sha256, signature {algorithm:Ed25519, key_id, value}|null. additionalProperties:false. Rutas resueltas bajo paquete; no comando de shell, sin valores secretos en documentos; entorno mediante EnvironmentConfig, valores no secretos o credential_reference de Credential Manager. Resolver secretos exclusivamente dentro del worker autorizado.

NDJSON JSON-RPC2 stdio: una línea UTF8 por frame, jsonrpc=2.0, id UUIDv7, method y params tipados en adapter-methods.json. stdout sólo frames, stderr logs filtrados. core.handshake {protocol_version, adapter_id, nonce} devuelve {protocol_version, adapter_version, methods, capabilities, nonce}; nonce exacto y major incompatible rechaza antes de IO. core.cancel {request_id} devuelve cancelled bool; core.heartbeat devuelve alive bool y running_request_ids. Una respuesta por id; eventos usan method=core.progress con {request_id, phase, completed_bytes, total_bytes, message_code}. Nunca mensajes de usuario o credenciales. Límite de frame1MiB, logs10MiB; trabajos largos devuelven Job/Plan, progreso no alarga timeout indefinidamente. Error JSONRPC code=-32000, data=LarmError; malformed=-32700, method=-32601, params=-32602. Tabla de métodos incluye firmas exactas; método no anunciado devuelve CAPABILITY_UNSUPPORTED sin éxito vacío.

Host mantiene proceso por adapter/version, cola bounded64, máximo4 RPC concurrentes salvo mutaciones serializadas por resource_id. Se usa cancel_grace_seconds=5; kill Job Object al vencer. Heartbeat10s y 3 ausentes provocan ADAPTER_CRASHED, journal/lock recovery y nueva generation. Permisos se evalúan antes de RPC y en cada IO del worker, pero esa validación NO es aislamiento del SO.

`source.download_chunk` es una firma source opcional de la revisión 1.1. El Core entrega source/job/plan/hash/revisión/ruta relativa, offset, máximo de bytes por bloque, validador de reanudación y aprobación nullable. El worker obtiene el contenido desde la fuente con sus credenciales autorizadas y devuelve como máximo 512 KiB codificados en base64 por respuesta NDJSON (frame completo menor de 1 MiB). No devuelve URLs firmadas, cabeceras de autorización ni secretos al Core. El Core exige que offset y validador coincidan antes de guardar; un validador cambiado obliga a reiniciar el artefacto desde cero. El método solo se invoca en adaptadores que lo anuncian, pasa por los mismos gates de paquete/confianza, Access, permisos y licencia, y no sustituye reserva, checksum ni staging P051.

Workers que ejecutan código no confiable requieren AppContainer Windows con capability network explícita, roots ACL concedidos a package SID y Job Object kill-on-close/límites memoria/procesos. Si AppContainer no es viable para ese runtime, modo TRUSTED_ONLY requiere aprobación explícita ligada a package/code hash, publisher, permissions, expires_at; GUI muestra limitación. Nunca etiquetar Job Object como sandbox de filesystem/red. Drivers, WSL global y software externo se adoptan con permisos read-only. Remote code/custom ops/custom nodes son deny por defecto; aprobación para una revisión no autoriza otra.

CUSTOM_RULES sólo JSON declarativo versionado validado: predicates campo/operator/value con operators eq, in, contains, range, exists; effect require/deny/limit; campos allowlisted format, architecture, quantization, capability, backend, os_build. Orden deny>require>limit, combinación AND y límites mínimos; no Python/JS/shell/regex arbitraria. Contradicción o campo desconocido rechaza. Declarative commands sólo executable allowlist+args con placeholders tipados MODEL_PATH, PORT, THREADS, CONTEXT, CONFIG_PATH; la URL base no admite token como texto.

Registro firmado P028 v1: registry_url=null deshabilita la consulta; configurarlo exige HTTPS con certificado válido y al menos una clave pública fijada en security.publisher_keys (mapa key_id → Ed25519 public key de 32 bytes, hex minúsculo, 64 caracteres). RegistryIndexEnvelope es cerrado {payload,signature}; RegistryIndexPayload es cerrado {schema_version="1.0",registry_id,sequence,issued_at,expires_at,packages,revocations}. El firmante firma exactamente los bytes UTF-8 de RFC8785(payload); RegistrySignature usa {algorithm="Ed25519",key_id,value}, con firma Ed25519 de 64 bytes codificada como hex minúsculo de 128 caracteres. La clave debe coincidir byte a byte con el pin local; el índice no puede añadir ni rotar pins. La URL configurada no admite userinfo, query ni fragment. El índice tiene máximo16MiB; admite hasta100000 paquetes y100000 revocaciones, IDs/versión únicos sin distinguir mayúsculas. issued_at no puede superar el reloj local por más de300s; expires_at debe ser posterior y no más de30d después de issued_at. Rechazar índice vencido, firma/schema inválidos y secuencia inferior. Repetir la misma secuencia y payload_sha256 es replay sin mutación; misma secuencia con otro hash es conflicto. Guardar checkpoint y revocaciones antes de publicar resultados. Las revocaciones se acumulan por registry_id y no se retiran por omisión en índices nuevos; su limpieza requiere intervención local explícita mediante administración de confianza P022. Los índices vencidos no autorizan nuevas instalaciones, pero el último estado de revocación persiste offline.

La gestión remota usa `GET /api/v1/adapters/registry` (`read`) y `POST /api/v1/adapters/registry/sync` (`adapters:write`, cuerpo cerrado `{}`, Idempotency-Key). El cliente usa TLS del sistema con validación de certificado, timeout de conexión de5s y total de20s, sin redirects ni cabeceras de autenticación; sólo acepta HTTP200 y JSON. Checkpoint, acumulación de revocaciones y evento/outbox se confirman juntos. La URL se vincula de forma única a un registry_id para impedir que un cambio de identidad reinicie la secuencia anti-rollback.

Cada RegistryPackageEntry cerrado tiene {id,version,url,sha256,package_sha256,signature}. sha256 es el SHA256 de los bytes del ZIP descargado; package_sha256 es el hash canónico de contenido P022 excluyendo manifest.json. signature es la firma esperada del AdapterManifest (o null para paquete sin firma), no una confianza adicional. URL de índice y paquete deben ser HTTPS; la URL del paquete debe compartir origen con registry_url o usar un origen exacto en security.registry_allowed_origins. Sin redirects ni auth forwarding. Una firma de paquete se valida de nuevo con P022 al instalar y ejecutar; un paquete sin firma queda UNTRUSTED y requiere la aprobación hashbound de P022 para ejecutar. Una firma con clave desconocida o inválida se rechaza. Revocation tiene target_type PACKAGE_SHA256 o PUBLISHER_KEY, target, revoked_at no puede superar el reloj local por más de300s y reason_code; una coincidencia bloquea nuevas ejecuciones y alerta incluso si el índice deja de estar disponible. El índice nunca marca un plugin OFFICIAL, VALIDATED o P026-qualified.

Importación inicial usa AdapterImportJournal cerrado, persistido en operation_journal con kind=adapter.import, id=job_id, phase de JobPhase, payload JSON validado por schema y plan_hash=SHA256(RFC8785(payload)); request, idempotency receipt de 30d y evento/outbox de aceptación se confirman juntos. Los pasos son QUEUED→INSPECTING→RESERVED→EXTRACTING→STAGED→PUBLISHING→COMPLETED; fallos previos al publish pueden acabar FAILED y cancelar sólo termina antes de PUBLISHING. Al reiniciar, QUEUED/RUNNING reanudan desde el snapshot privado y fase registrada. En PUBLISHING se reconcilia SQLite, filesystem y hash; no borrar a ciegas si el commit es incierto. JobState nunca devuelve package_path, rutas privadas ni payload del journal. Un import crea candidata INSTALLED side-by-side; no la selecciona, habilita, cualifica ni promueve. ZIP sigue límites P024 de 1GiB/100000 entradas/ratio1000, rechaza traversal, enlaces y reparse points, y se vuelve a verificar antes de publicar. Export sólo incluye manifest/assets y excluye configuración, credenciales y referencias a secretos.

API propia exige Bearer token incluso loopback en mutaciones y contenido sensible; health/live sólo estado binario público. Windows Credential Manager guarda secrets y metadata DB sólo credential_reference. Bootstrap usuario por named pipe ACL SID y handoff de un uso, sin token en URL/CLI. Scopes read, models:write, storage:write, runtimes:write, jobs:write, leases:manage, benchmarks:write, adapters:write, credentials:write, credentials:read, settings:write, admin. Broker sólo read+leases:manage. Principales MCP añaden mcp_scopes de §92 y audiencia restringida según contrato 11; la autorización efectiva es la intersección del permiso MCP y el scope API, incluso ante acceso API directo con ese principal. Scope no equivale aprobación de borrado/licencia: approval_id se liga a operation_digest, resource_ids, hash, actor, 900s.

Remote API default false; al habilitar exige HTTPS certificado válido, bind/IP explícitos, token rotatable scoped, origins exactas (ningún *), request body1MiB, rate60req/min/principal bursts20, no trust-forwarded headers salvo proxy pinned. TLS1.2 mínimo; no verify=false ni redirects con auth. Model endpoints bind loopback y secreto separado por lease; remotos sólo túnel/autenticación explícitos. Logs redacted headers/query/passwords/tokens; diagnostics no prompts, paths personales sólo con consentimiento y hashes. Importar origen desconocido no cambia trust.

TrustScore versión1.0 = publisher oficial verificado25 + fuente verificada20 + firma release válida20 + hash upstream comprobado20 + provenance completa15 - remote code requerido30 (floor0, max100). Cada señal UNKNOWN permanece desconocida y score=null si faltan fuente/hash/provenance; el informe conserva señales y riesgo. Community uploader no implica oficial, ni un score alto permite omitir sandbox/licencia/aprobación. No es una certificación de seguridad.

CredentialWrite sólo admite namespace larm/. Source accounts usan service=larm/source/{source_id}, username=account_id; endpoints usan larm/lease/{lease_id}. No sobrescribir ni borrar entradas ai-broker, dashboard u otras aplicaciones. Leer session_admin_token del Broker es sólo operación co-ubicada autorizada por Client_API, independiente del CRUD de secretos LARM.

P141: `AuthProbe` transporta `account_id` nullable junto a `source_id`, `auth_mode` y `credential_reference_id`. `NONE` exige `account_id=null` y referencia null. Una fuente privada debe declarar `source.account_id`; antes de iniciar el worker, el host comprueba que la cuenta pertenece a `source_id`, que su `credential_reference_id` coincide con el request y que la referencia guardada tiene `service=larm/source/{source_id}`, `username=account_id` y el tipo de secreto aplicable. El worker recibe sólo esos identificadores; resuelve el valor opaco desde Credential Manager con el `service` y `username` fijados por el host. El host incluye ese service como referencia exacta en `Access.secrets`; el manifiesto y la concesión deben declarar el mismo valor. No se acepta una referencia enviada por el cliente sin volver a resolverla en SQLite. Ningún secreto se incluye en RPC, variables de entorno, respuestas o logs.

Basic auth y OAuth code/device no se reemplazan por placeholders. Flujos del contrato08 incluyen sus límites y excepciones de callback. LARM rechaza transmitir credenciales Basic por HTTP salvo loopback de prueba explícitamente autorizado; production/private source exige HTTPS o canal SSH/SMB autenticado según host. API_TOKEN header va fijada por profile y no permite override hacia otro origin.

Import-only source sin search no devuelve un success fuera de schema ni lista vacía ficticia: descriptor search_applicable=false y source.search devuelve error normalizado UNSUPPORTED_CAPABILITY. Harness adapta el oracle a esa capacidad declarada y prueba get_model/manifest/size/import reales. No omite métodos que sí se anunciaron.

UNC/NAS privado usa auth_mode WINDOWS_INTEGRATED: identidad de Windows del worker/servicio o credential_reference explícita de Credential Manager para una conexión SMB acotada. No es HTTP Basic. El perfil fija server/share, identidad y permiso requerido; no introducir passwords en URLs o comandos. Reconciliar la conexión al rotar la credencial o cambiar el SID del servicio. PASSWORD describe el tipo de secreto, no un modo de autenticación.
