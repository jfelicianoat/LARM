## Comportamiento

P048 reconoce `Content-Range: bytes */N` en una respuesta 416. El total debe ser decimal válido y estar dentro de la cota de LARM. Sólo devuelve un EOF candidato si el offset coincide con N, el tamaño fijado —cuando existe— coincide y hay un SHA-256 fijado. Un total contradictorio o la ausencia de hash exige reiniciar; un encabezado ausente, malformado o desbordado produce error de protocolo. El cuerpo de error HTTP no se trata como contenido del modelo.

El EOF candidato no publica el archivo. El Core comprueba su tamaño y calcula el hash del fichero completo antes de confirmar `COMPLETED`. La nueva prueba del motor comprueba tanto el archivo íntegro como otro alterado de igual longitud y una contradicción de tamaño. Los parciales inválidos se rechazan y retiran. Se conserva el plan/revisión/hash aprobado al reiniciar desde cero.

La longitud declarada en un 416 describe la representación remota, sin acreditar el contenido local; véase [RFC 9110 §14.4](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.4). La condición de éxito con tamaño/hash está fijada también en el contrato local 02 §13. No se modifica el paquete contractual.

El adaptador de referencia permite inspeccionar el 416 dentro de `source.download_chunk`; mantiene el comportamiento anterior de los demás métodos. El servidor controlado genera respuestas HTTP reales, sin suministrar resultados de aprobación al worker.

## Ensayos independientes

Se mantienen todas las aserciones anteriores de ETag, hash corrupto, cancelación activa/en cola y recuperación tras reiniciar. Otra prueba, con daemon, base, principal y cualificación propios, comprueba:

1. Pausa con todos los bytes durables, HTTP 416 y publicación sólo después de verificar el contenido completo.
2. Mismo tamaño durable, alteración del parcial y HTTP 416: fallo de integridad, sin publicación/CAS y con journal/reserva cerrados.
3. Rechazo 416 antes de EOF: checkpoint cero, nueva lectura y verificación del SHA fijado.

La segunda fase conserva otra descarga pausada, comprueba sus bytes y reserva, y la cancela al terminar para cerrar todas las reservas y revocar el principal temporal. Usa seis variantes de datos propios, un único slot de transferencia y el paquete de referencia cualificado.
