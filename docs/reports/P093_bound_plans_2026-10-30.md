# P093 — planes ligados al worker y persistencia del preview

Fecha: 2026-10-30. Preparación independiente; P093 continúa BLOCKED_REAL y el objetivo global permanece activo. La API de producción todavía no conecta este repositorio con worker/admisión. No se declara CODE_PASS integral ni REAL_PASS.

## Cambios

`TransformationExecutionBinding` es un registro interno cerrado con instalación, run/hash de cualificación, hash del perfil y plan/hash privados del worker. `seal_bound_plan` incorpora esa identidad al digest confirmado sin añadir campos al DTO público `Plan`. Cambiar cualquiera de esas seis referencias invalida el sello. Un plan heredado sin ese campo mantiene representación y hash para recuperación; el nuevo repositorio exige binding presente.

`TransformationJob` conserva y valida ese binding con el adaptador resuelto. Un reintento ligado no puede degradarse a un plan sin binding. Se reproduce un fallo previo: un desbordamiento de row_version devolvía error después de modificar historial, snapshot e intento en memoria. Ahora se prepara una copia y sólo se sustituye el job al terminar correctamente; overflow o adaptador incorrecto dejan intacto el original.

`SqlTransformationPlans` guarda preview y evento/outbox juntos, sin job, reserva ni lock de ejecución. Comprueba sello, caducidad, identidad exacta de adaptador y recibo/journal/perfil P026 actual. Conserva el guard físico del host hasta COMMIT y lo revalida también en replay. El actor del perfil de backend y el propietario HTTP del plan se registran por separado; ningún flag JSON concede autoridad.

El preview es inmutable por ID: otro actor o contenido no lo sobrescribe; dos escrituras idénticas simultáneas producen un registro y un evento. La lectura privada se limita al propietario y valida versión, ID, hash, recursos y contenido sellado. Leer un registro histórico no autoriza ejecución.

No cambia el paquete3.12.1, las firmas del worker ni las tres rutas HTTP vigentes. La composición del daemon debe suministrar catálogo y archivos físicos, perfiles e instalaciones reales. Las fixtures de persistencia usan observaciones y guard deliberadamente simulados; no acreditan cualificación nativa ni conversión de modelos.
